## 踩过的坑

1. **Wolfram 四分类不能凭文献标签直接用**。随机初值下 Rule 232 会冻成条纹（类 2 行为）、Rule 250 直接收敛到全 1（类 1 行为），与常见"典型规则"清单不符。最终配图改用实测符合各类行为的 234 / 4 / 90 / 110，并在图注里说明"按最能看清行为挑选"。
2. **λ 的说法要改**：Rule 110 的 λ 是 **0.625**（5 个 1），不是 0.5。λ=0.5 那一格是 70 条规则，装了 Rule 30、90、54（类 3、3、4）。这样论证反而更硬——λ 在最小规则空间里只有 9 个取值，分辨力极差。
3. 用 Pillow 拼合多面板图时，**面板宽度必须 ≥ 步距**，否则面板互相压盖（第一次画滑翔机就踩了，272 宽配 268 步距）。
4. matplotlib 出图里，**画箭头前先算好文字包围盒**，λ 图的箭头直接压在数字上。
5. 类 1 若用会"死光"的规则（168），面板 90% 空白，网页上易被误认为图片没加载；改用收敛到全 1 的规则更稳。
6. 验证配图实际显示效果的办法：写一个 720px 宽的深色 HTML，用 `chrome --headless --screenshot --window-size=760,H` 截图，再按 1:1 裁剪查看。比空想可靠。

**这台机器 git 推不动的根因与解法（重要，以后会再遇到）**

1. `~/.gitconfig` 里原设 `http.proxy = http://127.0.0.1:7897`，该端口**当时不通 GitHub**（TCP 可连但 TLS 握手失败）。会话环境变量另指 `HTTP_PROXY=http://127.0.0.1:52763`（可用）。
2. 该 shell 的出口对 TLS 有中间层：即使清空代理、`http.proxy=` 直连，openssl 后端仍报 `self-signed certificate in certificate chain (19)`；schannel 则报 `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`（国内访问不到 CA 的 OCSP/CRL）。
3. **真正生效的组合**（缺一不可）：
   ```
   git config --global http.sslBackend schannel        # 必须显式为 schannel
   git config --global http.schannelCheckRevoke false  # 关掉吊销检查
   # 并清空 http.proxy / https.proxy
   ```
   只设 `schannelCheckRevoke=false` 而不显式写 `sslBackend` → 仍然失败。
4. 原配置备份在 `C:/Users/20504/.gitconfig.bak-20261030`。
