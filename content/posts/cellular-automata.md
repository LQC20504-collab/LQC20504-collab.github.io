1985 年前后，Stephen Wolfram 想找一个不依赖算法的随机数源。他给出的答案只有八行：`111→0`、`110→0`、`101→0`、`100→1`、`011→1`、`010→1`、`001→1`、`000→0`。

这八行后来真的被写进了 Mathematica，用来产生随机整数。它的全部信息量是一个字节：`00011110`，十进制 30。所以它叫 Rule 30。

这里有两件需要分开看的事。第一件：一字节的规则，凭什么能长出一片看不出周期的图案？第二件是它的反面——既然规则这么小，为什么我们算不出它第 10⁹ 行的第 500 个格子，非得从头一格一格跑过去？

前半篇回答第一个问题，讲局部规则怎么长出全局秩序；后半篇回答第二个，讲这种秩序为什么不能便宜地预测。而这两件事恰好是元胞自动机最容易被讲岔的地方：一边把"简单产生复杂"当口号喊，一边忽略了复杂之后的账单。

## 一、八个比特，一条随机数流

Rule 30 出自 Wolfram 1983 年那篇关于元胞自动机统计力学的论文（*Reviews of Modern Physics*）。它被反复引用，不是因为它在数学上多深刻，而是因为它把"规则的简单"和"行为的不简单"摆在了同一张图上：一条笔直的左边界，一片参差不齐的右边界，中间是从来没有重复过的内部。

先把规则表摊开。三个相邻格子的状态组合一共 8 种，从 `111` 到 `000`。给每一种组合规定一个输出——0 还是 1——就是一条完整的规则。把 8 个输出按 `111→000` 的顺序排成一串，就是一个 8 位二进制数，Rule 30 对应 `00011110`。**规则编号不是名字，它就是规则本身**，只是换了一种写法。

这串比特在 1985–86 年被提议用作流密码，后来普遍认为强度不足；它在 Mathematica 里的用途要朴素得多：当作一个便宜、免存储的伪随机整数源。

**需要说明的是：本文所说的"随机"指统计上难以预测，不涉及密码学强度；规则编号一律采用 Wolfram 编码；所引年份与结论以原始论文为准，不作转述式加码。**

要看清这件事，先把"规则"写成能计算的东西。

## 二、一条规则能有多短

元胞自动机的定义可以压到五行，而且没有一行需要公式：

- **格点**：一维整数位置 `i = 0 … N-1`。格距没有物理含义，它只是一个编号。
- **状态**：`S = {0, 1}`。只有两个，没有中间态，也没有"部分存活"。
- **邻域**：半径 `r = 1`，也就是 `i-1`、`i`、`i+1` 三个位置。决定一个格子命运的，只有它自己和左右两个邻居。
- **局部规则**：`f: S³ → S`，具体形式是一张 8 行的查表。写成函数就是 `x_i(t+1) = f(x_{i-1}(t), x_i(t), x_{i+1}(t))`。
- **更新方式**：同步。所有格点在同一个时刻、按同一张表、一起更新。没有先后顺序，也没有"谁先算谁占便宜"。

边界条件不是定义的附属品，而是一个必须显式做出的建模决定。常用的有三种：周期边界把两端接起来，写成 `x_{-1} = x_{N-1}`，等价于把格点排成一个环；固定边界在两端钉死一个值；无限格点则干脆没有边界，代码里用集合或稀疏表示来实现。

这里有两个结论值得写死。

第一，**这个系统没有全局方程**。不存在一个描述整体演化的公式，全部的"物理"就是那张 8 行的表。你想知道第 1000 代长什么样，唯一的路是走过去。

第二，**空间、时间、状态三者全是离散的**。这一点常被当成实现细节，其实它改变的是问题的性质：CA 是可精确计算的动力系统，没有舍入误差，没有"数值不稳定"，跑一万次结果一模一样。这与用差分法解微分方程有本质区别——后者每一步都在丢精度，你永远在近似一个你摸不到的真解。

## 三、一维世界：256 条规则

三个格子、每个格子两种状态，一共 `2³ = 8` 种邻域组合。每种组合对应一个输出，于是规则总数是 `2⁸ = 256` 条。这个数字小到可以穷举，也就意味着**一维初等自动机是一个已经被人走完的房间**——没有未知的角落，只有解释不完的现象。

编号方法前面已经说过，这里补一个对照：Rule 110 的二进制是 `01101110`，所以它的规则表是 `111→0`、`110→1`、`101→1`、`100→0`、`011→1`、`010→1`、`001→1`、`000→0`。只差几个比特，和 Rule 30 就是两个世界。

第一个反直觉点在这里：**编号相邻，行为可以毫无关系**。Rule 29 和 Rule 30 是邻居，但它们的长期形态没有任何可推断的连续性。规则空间上不存在"距离"这个概念，所以"把规则稍微调一点"这种想法在一维二态的情况下根本无从谈起——你只能换一条完全不同的规则，然后重新观察。

下面这段代码就是这套定义的直接翻译，把 `30` 换成 `110`、`90`、`184` 就能复现本文提到的其它例子，逻辑一行不用改：

```python
"""一维初等元胞自动机：通用引擎 + Rule 30 演示（仅用标准库）"""


def run_elementary(rule, width=79, steps=40):
    """返回 steps 行、每行 width 个 0/1 的演化历史。"""
    # 规则表：8 种邻域 (111, 110, ..., 000) 依次对应 rule 的 8 个二进制位
    # k = 7 对应 111，k = 0 对应 000，所以可以直接拿邻域值当索引
    table = [(rule >> k) & 1 for k in range(8)]

    # 初始构型：只在最中间放一个活胞，其余为 0
    cells = [0] * width
    cells[width // 2] = 1

    history = [cells]
    for _ in range(steps - 1):
        nxt = [0] * width
        for i in range(width):
            # 取左、中、右三个邻胞；越界时用周期边界回绕
            left = cells[(i - 1) % width]
            mid = cells[i]
            right = cells[(i + 1) % width]
            # 三位拼成一个 0..7 的整数，查表得到下一代
            nxt[i] = table[(left << 2) | (mid << 1) | right]
        cells = nxt
        history.append(cells)
    return history


def show(history):
    """把演化历史打到终端：活胞用 #，死胞用 ."""
    for row in history:
        print("".join("#" if c else "." for c in row))


if __name__ == "__main__":
    show(run_elementary(30, width=79, steps=40))
```

`table[(left << 2) | (mid << 1) | right]` 这一行是全篇的核心：它把"查表"压成一次位移加一次或运算，也把第二节那句"规则就是一张 8 行的表"变成了可执行的事实。`width=79` 是刻意的——每次演化光锥左右各扩一格，40 步正好扩 39 格，79 列刚好装得下，终端里不会折行把图案撕成两半。

### Rule 30 —— 中心列被当成随机数

![Rule 30 从单个活胞出发演化 100 代的时空图](/images/cellular-automata/rule30.png)

*图 2：Rule 30 从单个活胞出发的 100 代演化，时间向下。左边界是一条笔直的斜线，因为 `100→1` 让最左边的活胞永远不会失传；右边界参差不齐；内部夹着的三角形空洞是自相似结构，但整体从不重复。*

这张图最值得看的是"同一条规则、两种外观"：左边有序，右边无序，而它们之间没有任何分界。

中心列之所以能被当作随机源，靠的是三条：没有可辨周期、统计检验过得去、实现成本极低（每个格子一次三位查表）。它至今没有闭式解，也没有比逐格演化更快的通用算法。这一点先记着，第十节要回来算账。

### Rule 110 —— 图灵完备，但不是万能计算器

Rule 110 在 1994 年由 Matthew Cook 完成图灵完备性的证明，2004 年发表在 *Complex Systems* 上。这个结果经常被简化成一句"一条简单规则能算任何东西"，听起来像是给了计算机一张新的许可证。

它的机制值得说清楚：Rule 110 的演化背景是一层周期性的"以太"，上面跑着若干种可以传播的滑翔结构。这些结构相互碰撞时的行为，足以实现逻辑门。计算不是靠某个巧妙的编码，而是靠碰撞。

但这是第二个反直觉点，而且它比第一个重要得多：**图灵完备只保证"能把任意计算编码进初始构型"，不保证这件事值得做。** 具体代价有三层——编码极其繁琐，速度以"每个逻辑门多少代"计，而且停机不可判定，你无法预知它算完没有。所以"Rule 110 是一台计算机"是一句理论上成立、工程上无意义的话。

它真正证明的是**表达能力的下限可以极低**：你不需要复杂的东西来表达复杂的计算。它没有证明**计算可以很便宜**。这两句话经常被混成一句，而混掉之后，整个论证就只剩下好听。

## 四、二维世界：生命游戏与「邻居」的算法

1970 年，Martin Gardner 在《科学美国人》的数学游戏专栏里把 Conway 的生命游戏推给了公众。它的规则通常记作 `B3/S23`：死胞周围恰好 3 个活胞时诞生（Birth on 3），活胞周围有 2 或 3 个活胞时续命（Survival on 2 or 3），其余一律死亡。

值得注意的是"邻居"这件事本身就是一个建模决策。**Moore 邻域**数上下左右加四个斜角，一共 8 个；**von Neumann 邻域**只数上下左右 4 个。换一种数法就是换一个模型，规则表要重写，行为也完全不同。这看起来像细节，其实是整套建模里最容易被默默替掉的一环。

二维世界里的图案分三种命运：

- **静物**：比如 block（2×2 的方块）和 beehive，逐代不变，是这个世界的岩石。
- **振荡子**：比如 blinker（三个连成一线），周期 2；pulsar，周期 3。它们活着，但不走。
- **滑翔机**：五个活胞组成的形状，每 4 代回到自己的原形，整体沿对角线挪一格。

![生命游戏中滑翔机连续五代的演化](/images/cellular-automata/life-glider.png)

*图 3：滑翔机在第 0 代到第 4 代之间的形态。形状每一代都在变，但第 4 代与第 0 代完全相同，只是整体平移了 (1, 1)。*

滑翔机是生命游戏能承载计算的根本原因：形状不变、位置改变，这两件事合起来就是一个可以搬运的信号。滑翔机当信号线，滑翔机枪当节拍器，碰撞当逻辑门，Paul Rendell 甚至真的在生命游戏里造出了一台图灵机。

第三个反直觉点由此而来：**给定任意初始图案，判断它最终会不会彻底死光，一般不可判定。** 这不是因为问题难，而是因为它足够通用——通用性把停机问题一并带了进来。你没法写一个程序，对所有初始图案都给出"会死光"或"不会死光"的确定答案。

用集合表示活胞，这段代码短到可以整段读完。集合的好处是它等价于无限平面，天然没有边界，也就不需要写越界判断：

```python
"""生命游戏（Game of Life）：集合表示活胞，B3/S23 规则（仅用标准库）"""


def step(alive):
    """推进一代：返回新的活胞集合。"""
    # 统计每个位置的邻居数；只记录被数到过的位置
    counts = {}
    for (x, y) in alive:
        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                if dx == 0 and dy == 0:
                    continue  # 跳过自己
                p = (x + dx, y + dy)
                counts[p] = counts.get(p, 0) + 1

    # 诞生：死胞周围恰好 3 个；续命：活胞周围 2 或 3 个 —— 即 B3/S23
    return {p for p, n in counts.items() if n == 3 or (n == 2 and p in alive)}


def show(alive, w=24, h=14):
    """把当前状态画成字符网格。"""
    for y in range(h):
        print("".join("#" if (x, y) in alive else "." for x in range(w)))


if __name__ == "__main__":
    # 滑翔机的 5 个活胞：每 4 代整体平移 (1, 1)
    glider = {(1, 0), (2, 1), (0, 2), (1, 2), (2, 2)}
    for gen in range(5):
        print(f"generation {gen}")
        show(glider)
        glider = step(glider)
```

`n == 3 or (n == 2 and p in alive)` 这一行就是 `B3/S23` 的逐字翻译，代码即定义。若要改成有限网格，就得显式规定边界行为——环绕或者死亡。这里用集合，等于选择了"无限平面"，代价是每代都要重建字典，换来的是逻辑上的一干二净。

## 五、四种命运：Wolfram 分类与它的边界

Wolfram 在 1980 年代把一维初等自动机的长期行为归成了四类。这个分类不是推出来的，是看出来的：

| 类别 | 长期行为 | 典型规则 | 直观描述 |
|---|---|---|---|
| 1 | 收敛到均匀态 | 0、32、168 | 很快死光或者长满，图案消失 |
| 2 | 周期或局部稳定结构 | 4、108 | 冻结成条纹、块状，局部重复 |
| 3 | 混沌，统计上均匀 | 30、90、150 | 无周期，看不出结构，像噪点 |
| 4 | 局部结构与混沌共存 | 54、110 | 结构在噪声背景上传播、碰撞 |

![四类元胞自动机的典型形态对比](/images/cellular-automata/four-classes.png)

*图 4：四类行为的典型形态，都从同一随机初值出发，演化 130 代。类 1 在十几代内收敛到均匀态；类 2 冻结成竖条纹；类 3 是致密噪点；类 4 的噪声里留着可以传播的斜向结构。四个面板分别用 Rule 234、4、90、110——是按"从同一个初值出发最能看清行为"挑的，不代表每一类只有这一条代表。*

必须说清楚这个分类的边界。它是**观察之后的归纳，不是定理**：类 2 与类 3 之间、类 3 与类 4 之间都存在难以归类的中间态，而且分类本身依赖初始条件——同一条规则换个初值，观感可能就变了。更麻烦的是，Culik 与 Yu 在 1988 年证明，一般情形下这类分类判定问题本身是不可判定的。换句话说，你没法写个程序，对任意规则都自动判出它属于哪一类。

第四个反直觉点在表格的最后两行之间：**"复杂"不等于"随机"**。类 3 是随机，类 4 是"有结构但不可预测"。前者好看但没用，后者才是计算的温床——滑翔机、以太、碰撞，全在类 4 里。把这两者混成一个"复杂"，后面所有的推论都会走偏。

## 六、λ 与「混沌边缘」：一个漂亮但站不住的强命题

Chris Langton 在 1990 年提出过一个参数，想把"规则有多活跃"量化。定义很朴素：规则表里，输出不等于静止态的转移所占的比例，记作 λ。

用 `K` 表示状态数、`N` 表示邻域大小，`n_q` 表示全部映射到静止态的规则数，那么 `λ = (K^N - n_q) / K^N`。λ 接近 0，规则几乎总把格子打回静止；λ 接近 1，规则几乎总在翻转。

他扫描了不同 λ 下的规则，看到的是一个相当漂亮的图景：λ 小的时候系统冻结，落进类 1 或类 2；λ 大的时候剧烈振荡；而在中段某个位置，类 4 的规则开始出现。由此他提出"混沌边缘"（edge of chaos）：计算能力在有序与混沌的相变点附近最大。

这个故事被引用了三十多年，但它有一个在最小规则空间里就能看出来的漏洞。

一维、半径 1、二态的情况下，规则表只有 8 个转移，所以 **λ 只能取 9 个值**：0、1/8、2/8，一直到 1。而且分布是二项式的——`λ = 0.5` 那一格装了整整 70 条规则。

![256 条初等元胞自动机规则按 λ 的分布](/images/cellular-automata/lambda.png)

*图 5：256 条初等规则按 λ 的分布。中间那根柱子（λ = 0.5）装了 70 条规则，Rule 30、Rule 90 和 Rule 54 都在里面——前两条是类 3，后一条是类 4。*

这就是问题所在。Rule 30 是类 3，Rule 90 也是类 3，Rule 54 是类 4，它们的 λ 全都等于 0.5。Rule 110 落在另一格，λ = 0.625，那一格里也有 56 条规则。**这个指标在最小的规则空间里几乎没有分辨力**：它把混沌、复杂和图灵完备一起塞进了同一个箱子。

一个更直接的检验来自 Mitchell、Crutchfield 和 Hraber 在 1993 年的工作。他们用遗传算法去演化执行"密度分类"任务的 CA，结果是最优的规则并不集中在 λ 的临界点上——多个不同的 λ 值都能达到同等性能。也就是说，**"边缘 = 最优"这个等式没有得到证据支持**。

措辞上要留一分余地：被削掉的是"λ 能预测计算能力"这个强命题，不是相变视角本身。有序相与混沌相确实存在，相变也确实是个有用的框架。失效的是把它当成一把可以量出复杂性的尺子——至少在一维二态的规则空间里，这把尺子的刻度太粗了。

## 七、地理学早就走到了这里

地理学界用 CA 做空间建模比计算机学界更早，也更认真。原因很实际：**栅格数据本身就是一个 CA 的格点层**。一个 GeoTIFF 里，每个像元是一个格点，波段值是状态集合，3×3 窗口是邻域，焦点统计（Focal Statistics）就是给每个格点套同一个局部算子、然后同步更新——正好是第二节那五个要素。

更直白的对应在邻接关系里：ArcGIS 的 queen 邻接就是 Moore 邻域，rook 邻接就是 von Neumann 邻域。你写空间权重矩阵 `W` 的时候，写的就是第四节的邻域定义。

### Tobler 与「细胞地理学」

Waldo Tobler 在 1979 年写过一篇 *Cellular Geography*，比 Gardner 介绍生命游戏只晚九年。他的主张不是"我要模拟城市"，而是一个方法论判断：地理空间可以离散成细胞，地理过程可以写成局部转移规则，于是地理学能借 CA 做可计算的实验。

这件事有它的逻辑必然性。Tobler 更出名的是地理学第一定律——"一切事物都与其他事物相关，但近处的事物比远处更相关"。这句话本身就是对局部性的辩护：既然近处的相关性占主导，那么"只看邻域"就不是简化，而是抓住了主要矛盾。CA 的合法性建立在同一个前提上。

### 从细胞到城市

White 与 Engelen 在 1993 年用 CA 模拟城市土地利用的演化，第一次让"细胞"和"城市形态"直接对上；Batty 与 Xie 在 1994 年那篇 *From Cells to Cities* 里引入分形几何，说明城市形态的自相似性可以由局部规则生成。这两步之后，CA 在地理学里不再是隐喻，而是工具。

### SLEUTH —— 地理界最出名的那个 CA

SLEUTH 是城市增长模拟里最有名的 CA 模型，名字是六层输入的缩写：坡度（Slope）、土地利用（Land use）、排除层（Exclusion）、城市范围（Urban）、交通（Transportation）、山体阴影（Hillshade）。它用四类增长规则驱动：自发增长、扩散增长、有机增长、交通影响增长，再加一个自修正机制，让增长速率随历史趋势调整。

校准是在已知的历史年份上做拟合——暴力搜索或者遗传算法，把系数调到"能重现 1985 到 2010 年的城市边界"为止。输出不是一个确定的未来，而是一张"某个格子被转化成城市的概率"。

CA-Markov 是另一条常见路线：Markov 链负责定总量和转移比例，CA 负责定空间落点。分工清楚，但它继承了 Markov 的假设——转移概率不随历史变化。

**一点保留**：这类模型的可信度来自校准与独立验证，不来自规则写得像不像城市。看起来合理但没做过留出年份检验的模拟，只是一张好看的图。

### 规则从哪来 —— GeoCA 与 ANN-CA

这才是 CA 在地理应用里真正的死穴。一维初等 CA 的规则表只有 8 行，可以穷举；城市模型的规则表里，土地利用有 6 类、邻域半径可能 5 格、再加上十几个驱动变量，规则空间大到无法枚举。**"把规则写出来"这件事本身变成了研究课题。**

两条主要路线：

- **地理元胞自动机（GeoCA）**：周成虎等人在 1999 年的《地理元胞自动机研究》里把这套方法系统化，把 CA 与 GIS 的栅格运算绑在一起，给出地理 CA 的概念框架与实现路径。
- **ANN-CA**：黎夏与叶嘉安用神经网络从两期历史土地利用数据里学出转换概率，再由 CA 做空间分配。这换掉了一个前提——规则不再靠专家拍板，而是从数据里拟合出来。

代价要写清楚：规则从一张可读的 8 行表，变成了一个几百个权重的矩阵。**可解释性换来了拟合能力**。你不再能指着某一行说"这个格子因为这三个邻居才变"，只能看特征重要性。这是地理 CA 与 Rule 30 最大的分野：前者是统计模型，后者是计算模型。

### 尺度与 MAUP

最后是一个地理学特有的麻烦。CA 的格距是人为的，而地理学早就知道这件事有多要命——可塑性面积单元问题（MAUP）：同一片区域，用 30 m 像元还是 1 km 像元做单元，聚合结果和统计关系都会变。

CA 把这个问题放大了一档：不仅统计量变，**演化路径本身也变**，因为格距和邻域大小一起决定了信息传播的速度与范围。所以模型校准得好不好，不能只看"重现了历史"，还要看"换个分辨率还站不站得住"。这一条在地理 CA 的文献里被反复提起，真正执行的却没几个。

## 八、把 CA 当工具：车流与疫情

地理之外，还有两个被反复引用的战场：交通与疾病传播。它们的共同点是机制本来就长成 CA 的样子——个体按局部规则移动、感染、恢复，没有谁在指挥全局。

### 交通流 —— Rule 184 与 Nagel–Schreckenberg

Rule 184 是一维二态规则，语义朴素到可以直接念出来：前面有车就停，没车就走。它的流量–密度曲线呈倒 V 形，峰值出现在密度 `ρ = 0.5`——一半车道被占满的时候通行量最大。这是 CA 少见的给出**定量正确**结论的例子，不是"看起来像"，是对得上。

Nagel 与 Schreckenberg 在 1992 年加了一味料：随机慢化概率 `p`。加上之后，"幽灵堵车"就能自己长出来——没有瓶颈、没有事故、没有红绿灯，一段均匀车流里会自发涌现出向后传播的拥堵波。这是 CA 最漂亮的时刻之一：一个宏观现象，不需要任何宏观原因。

**一点保留**：能复现基本图的形状，不等于能预测某条路的某个早高峰。前者是机制验证，后者需要标定和实时数据。

### 流行病与生态 —— 空间结构改写阈值

格点上的 SIR 模型和接触过程，与均场模型的差别只有一个：局部传播。均场模型只看 `R0`，格点模型还看连通性——同样的人数、同样的传染率，只要空间结构不同，爆发阈值就不同。

森林火模型（Drossel–Schwabl）是自组织临界的经典例子：不需要外部调参，系统自己滑到临界态，火势大小呈现幂律分布。

**一点保留**：这类模型的价值在机制对比——有无空间结构、有无随机性，结论差在哪里——不在预测具体数字。

## 九、两种身份，四条局限

元胞自动机在文献里其实扮演着两个完全不同的角色，混用会带来很多误会。

**身份一：计算模型。** 它与图灵机、λ 演算并列，用来讨论可计算性与复杂度的下界。Rule 110 的意义就在这里——它说明表达能力的下限可以低到一条 8 比特的规则。

**身份二：建模工具。** 它与微分方程并列，用来描述具体系统。它擅长的是"个体异质 + 局部交互 + 空间结构"，不擅长连续守恒量——模拟流体得靠格子气或格子玻尔兹曼做折中。

一条可操作的判据：主要矛盾是"个体与局部规则"，用 CA；主要矛盾是"连续场的守恒律"，别用 CA 硬凑。

然后是四条必须承认的局限：

- **规则空间爆炸**：二态 Moore 邻域有 `2^9 = 512` 种邻域组合，规则总数是 `2^512`。这个数字大到不可能穷举，实际能用的只有 totalistic 或 outer-totalistic 这类强约束的子集。而约束本身就是建模假设，不是自然规律。
- **尺度是人为的**：格距与时间步长没有物理依据，结果对离散化敏感，缺少连续方程那种尺度不变性。第七节那个 MAUP 就是它在空间数据上的具体形态。
- **验证薄弱**：相当多的应用只做到"看起来像"的定性比较，缺少可以被反驳的定量预测。
- **计算不可约**：多数有趣规则的长期行为没有闭式解，只能跑。预测的成本等于模拟的成本——这是 Wolfram 用了很多篇幅论证的一点，也是它最实用的一个结论。

最后单独说一句"涌现"。这个词在 CA 的语境里被用得太顺口了。"秩序从局部规则中涌现"听起来像结论，其实只是把"宏观模式没有写进规则里"这句话换了个说法。一个可操作的标准是：指出哪一条局部交互、通过哪个中间量、产生了哪个宏观指标。做不到这三件事，就还停在描述，没有到解释。

## 十、回到那八个比特

Rule 30 今天仍然是一个好用的随机源。但它真正有价值的不是"简单产生复杂"这句口号，而是它逼出来的两个判断。

第一，**简单性属于规则，复杂性属于轨迹**。规则只有 8 个比特，轨迹从来没有重复过。这两件事可以同时为真，不矛盾，也不需要神秘化。

第二，**预测可能和模拟一样贵**。这不是技术的暂时不足，而是这类系统的结构性特征。你想要第 10⁹ 行，就得走 10⁹ 步。

所以看待元胞自动机，取决于你拿它当哪一种身份。用计算模型的眼光看它，该问"它能算什么、代价多大"；用建模工具的眼光看它，该问"它校准过吗、能不能被证伪"。问错问题，CA 就只剩下一堆好看的图案。
